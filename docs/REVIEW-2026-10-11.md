## 0. Решение по сжатию

A/B 2026-10-11 (36 живых прогонов + офлайн-корпус): оставляем Headroom (транспорт, CCR/retrieval) + SuperCompress (компрессор). Headroom-native: ~18% сжатия, на логах модель всегда идёт в retrieval (+61% input). SC: −13% input / −40…−63% uncached на логах; слабое место — лишний retrieval на коде и в Claude. Переключатель `AGENT_CONTEXT_COMPRESSOR=native` — только для бенчмарка (см. B6).

## B. Высокий / средний приоритет

- **B1 Update trust [код].** Digest и manifest — из одного источника (GitHub), без подписи. Self-test кандидата идёт с настоящим `AGENT_CONTEXT_HOME` до активации (update.js:156). Лок держится до ~8 мин. → Тест кандидата в изолированном HOME; подписанный manifest (ed25519, ключ в клиенте) или npm provenance; staged rollout (canary → 10% → 100% по `hash(machine_id)`), kill switch в manifest.
- **B2 Update failure modes [код].** Сбой — повтор только через 24 h; `stage-*`, старые версии, venv, `backups/`, `key-*.before` (plaintext ключ!) не чистятся; minor bump = `migration_required` навсегда; rollback одноуровневый и выключает автообновление навсегда. → Prune (держать 2 версии), удалять `key-*.before` после успешной проверки, backoff 1h/6h/24h, повторное включение автообновления после следующего успешного релиза.
- **B3 Doctor не проверяет маршрутизацию [код].** `ANTHROPIC_BASE_URL`, Codex `model_provider`/`base_url` не проверяются; drift не чинится (`--fix` восстанавливает только отсутствующие файлы). → Добавить проверки + reapply при drift; end-to-end probe: синтетический запрос через proxy.
- **B4 Нет бюджета на запрос (HTTP path) [код].** N tool results × 20 s. → Общий бюджет на запрос (например, 20 s), остаток — passthrough.
- **B5 Повторное сжатие истории [код+docs].** `cache_enabled=False`, `session="headroom"` → неизменённая история может сжиматься заново каждый ход. Claude docs: переписывание прежних messages ломает prompt cache и thinking signatures. → Сжимать только новый tool result; кэш по hash контента.
- **B6 Env leak [код].** `AGENT_CONTEXT_COMPRESSOR=native` наследуется из `process.env` (run.js:70) → случайная переменная включит Kompress в production. → Сервис строит env по allowlist; переключатель только в бенчмарке.
- **B7 Холодный старт [код].** SessionStart 45 s не покрывает сборку venv (>4 мин после update). → Prepare venv в фоне во время update (до активации), SessionStart только проверяет и не ждёт.
- **B8 Скрытые fail-open [код].** SC skip (`no_gain`, `empty`, `too_large`) пишет инцидент с категорией вне allowlist — молча теряется (supercompress.js:8, incidents.js:20). Hermes `remember` → `None` = сжатие тихо выключено. → Явные метрики skip; Hermes — инцидент `lifecycle_failed`.

## C. Инциденты: новая схема без спама

Сейчас [код]: fingerprint `sha(component, operation, category, agent)` без версии/платформы; доставка через `gh` от GitHub-аккаунта пользователя (публично связывает личность + `machine_id`); opt-out; «+1» = новый комментарий; `create_unknown`/`comment_unknown` никогда не реконсилируются.

Предлагаемая схема [мнение, на основе практик Sentry/GitHub]:

1. **Клиент.** Fingerprint = `sha(code, component, operation, major.minor, platform)`. Allowlist-полей, без текста/путей/env. Отправка одного fingerprint не чаще 1/сутки с машины. Локальная очередь с backoff. Команда `agent-context incidents show` — что уйдёт.
2. **Relay (Cloudflare Worker + Durable Object на fingerprint).** Без секретов на клиенте. Валидация схемы, rate limit по `machine_id`/IP, атомарные счётчики: occurrences, unique machines, версии, first/last seen.
3. **GitHub App (ключ только в Worker).** Issue создаётся только при пороге (≥3 машины или ≥1 на latest). Счётчики — таблица в теле issue, обновление раз в час; не комментарий на каждое событие. Метки `fp:`, `sev:`, `version:`.
4. **«+1 от агента».** Анонимно через relay = +1 к unique machines. Под своим GitHub — только вручную/с согласия (`gh` reaction 👍); одна реакция на пользователя.
5. **Связка с релизами.** Продвижение staged rollout разрешено, только если на новой версии нет нового fingerprint N часов; иначе kill switch / откат.

Альтернатива без своей инфраструктуры: Sentry SaaS с ручным `fingerprint` (дедуп и счётчики из коробки), публичный DSN + inbound rate limits. Токен GitHub в пакет — **никогда**.

## D. Рекомендуемые настройки агентов

### Claude Code [docs]
- Hooks: `command` по умолчанию 600 s, UserPromptSubmit 30 s; fail-open по умолчанию. Наш SessionStart: оставить 45 s, но сделать быстрым (B7). Логирование/отчёт инцидентов — `"async": true`.
- Proxy-требования: пересылать `anthropic-*` headers/body без изменений, не буферизовать SSE, не удалять `ping`, не переписывать `system`/`tools`/прежние messages, отдавать ошибки как есть (Claude Code ретраит по тексту). `cache_control` сохранять. → Добавить в qualification тест «cache read > 0 на 2-м ходе».
- Desktop app игнорирует `ANTHROPIC_BASE_URL` — уже документировано; оставить предупреждение.
- Env (предложение): `MCP_TIMEOUT=60000` (retrieval MCP на Python), `MCP_TOOL_TIMEOUT=300000`; `BASH_DEFAULT_TIMEOUT_MS`, `CLAUDE_CODE_PROMPT_CACHE_TTL` — пользовательские, не навязывать.
- Модели: Opus 5.5 / Sonnet 5.5 — effort `medium` по умолчанию, `high` для сложного; Fable 5.1 — `high`, длинные автономные задачи. Модель/effort пакетом не навязывать.

### Codex [docs]
- `features.hooks` (не `codex_hooks`). Hook `timeout` по умолчанию 600 s; задать явно. `async = true` для фоновых действий.
- `[model_providers.agent_context]`: `stream_idle_timeout_ms = 300000`, `request_max_retries = 4`, `stream_max_retries = 5` — явно. `supports_websockets = true` только если proxy полностью держит Responses WS (close codes); иначе retry storm «Reconnecting n/5». Добавить fallback-профиль с `supports_websockets = false`.
- MCP: `startup_timeout_sec = 30`, `tool_timeout_sec = 60` для `headroom`.
- Compaction-запросы пропускать без сжатия.
- Profiles теперь отдельными файлами `$CODEX_HOME/<name>.config.toml` — проверить совместимость с версией.

### Hermes [docs]
- `plugins.hook_callback_timeout` по умолчанию 30 s — наш `pre_llm_call` lifecycle (40 s) **превышает** его → callback будет брошен. Lifecycle сделать асинхронным/≤20 s; `transform_tool_result` (25 s) тоже близко к лимиту → ≤20 s.
- Есть встроенное `compression.*` Hermes — проверить, что не дублирует наше сжатие (`possible_double_compression`).
- MCP: явные `timeout`, `connect_timeout`, `env` (stdio не наследует shell env), `tools.include`.

# Проверка Agent Context 0.1.14 на рабочих хостах

11 октября 2026, Asia/Bangkok. Пакет обновлён на Mac, FRA и native Windows. Полная квалификация не завершена: Codex на Mac сохраняет занятый сервис 0.1.11, retrieval внутри агентов WSL блокируется разрешениями, Claude на Windows не имеет разрешения на retrieval, холодный запуск Hermes на FRA обнаружил дефект изоляции Python.

## Версия и изменения

Установлен исходник `79cf442ad46549f209229ef7b8ccb99a316a6290` из `taskqorg/agent-context`, версия 0.1.14. Mac и FRA получили один проверенный архив SHA256 `5a50e4bc895adfbff9b46316f9762322a44becc4c54eafba205d52f7820a0ee3`. Windows использует отдельную сборку того же SHA. Это ручная установка рассмотренного исходника, не проверка идентичности опубликованному подписанному архиву.

Setup применяет автоматическую интеграцию установленных агентов: Codex provider и lifecycle, Claude proxy и lifecycle, Hermes native plugin. Retrieval остаётся отдельным разрешаемым инструментом. В текущей версии исправлен адрес anonymous relay; текущий исходник также удаляет вспомогательный manifest, перенаправлявший код на сторонний хост. Наличие этих изменений не доказывает надёжность каждого runtime.

## Проверки сжатия и инцидентов

Прямой маршрут через сервисы 0.1.14 на Mac и FRA: 11 644 -> 922 символа, пользовательский запрос неизменен, release `amber-47`, port `6543`, retry limit `2` сохранены. Retrieval вернул точный исходник. Native Hermes read_file на FRA: 12 473 -> 1 086 символов, правильный ответ. Windows direct proxy: 13 091 -> 909 символов, точный ERROR и оригинал сохранены.

Langfuse API подтвердил SPAN 0.1.14 для Codex, Claude Code и Hermes с идентичностью синтетических сессий. Host tag остаётся `unknown`. Эти оценки размера сжатия не являются экономией model-input tokens или денег; парный benchmark задачи здесь не выполнялся.

В отдельном AGENT_CONTEXT_HOME смоделированы отказы: оригинал сохраняется, query не меняется, повторные события объединяются, недоступный relay оставляет очередь, последующая mock-доставка помечает события reported, повторная отправка отсутствует. На Windows дополнительно проверены timeout и lost_critical_evidence. Синтетические инциденты в публичный tracker не отправлялись.

На FRA реальные сбои запуска Hermes автоматически создали `startup_failed` для `ensure`, `serve` и `lifecycle`. Штатный `incidents report` доставил три fingerprint через настоящий relay. `configuration_drift` остаётся локальным событием по правилам пакета. Дедупликация ограничивает доставку одним разом в сутки; поздние повторения могут ждать следующего окна.

## Дефект запуска Hermes на FRA

Hermes передаёт дочерним процессам PYTHONPATH с библиотеками своего Python 3.14. Headroom имеет private venv Python 3.12, но наследует этот путь. FastAPI и Pydantic загружаются из окружения 3.14, затем импорт `pydantic_core._pydantic_core` падает. Воспроизведение с этим PYTHONPATH завершилось ошибкой; импорт с чистым окружением прошёл.

Сервис запущен штатным `proxy ensure hermes` без PYTHONPATH и PYTHONHOME. Три собственных неуспешных supervisor процесса завершены через SIGTERM после проверки пользователя, точного launcher argv, загрязнённого PYTHONPATH, отсутствия дочерних процессов и отличия от здорового сервисного PID; завершение подтверждено. Код пакета не исправлялся. Новый холодный запуск из Hermes может повторить дефект. Надёжность автоматического восстановления пока не квалифицирована.

Первая попытка установки FRA также остановилась при заполненном диске. Незавершённое окружение этой попытки удалено; рабочее и rollback окружения сохранены. Когда доступное место восстановилось, повторная штатная установка прошла. После отдельного разрешения владельца удалено неиспользуемое окружение `95b6f317bddf2f51` прежней версии 0.1.10: процессы, текущий runtime и выбранный откат его не использовали. Освобождено около 786 МиБ, после очистки доступно 7,57 ГиБ; 0.1.14 и откат 0.1.11 сохранены. Doctor после очистки healthy, warnings и issues пусты.

## Процедура приёмки следующего обновления

Каноническая установка и ограничения: [INSTALL.md](../INSTALL.md). Проверять native Windows и WSL, каждый фактический профиль и версию живого сервиса отдельно.

1. Закрепить рассмотренный SHA или проверить подписанный архив. Запустить `npm test`, затем `npm pack`; изменения проверять в изолированном AGENT_CONTEXT_HOME и npm_config_prefix. На текущем исходнике Mac: 72 PASS. Упакованный FRA: 69 PASS, 1 штатный skip Git checkout; Python Headroom 8 PASS, Hermes plugin 3 PASS.
2. Проверить зависимости, наличие локального ключа без вывода значения, конфликты и выбранные агенты. Выполнить setup, затем `doctor --fix --live`. Сравнить выбранный пакет и живые сервисы; updateDeferred означает незавершённое переключение.
3. В свежем native сеансе каждого агента прочитать разрешённый synthetic fixture. Подтвердить фактическое сжатие tool result, неизменный query, правильный ответ и точное восстановление оригинала. Не менять login, модель или глобальные approvals ради прохождения.
4. В отдельном окружении проверить fault/fallback/recovery, очередь, очистку публичных полей и дедупликацию через mock tracker. Настоящую доставку проверить на реальном инциденте, не публикуя фиктивную аварию.
5. Проверить холодный запуск, затем штатный Hermes -> TaskQ -> Codex worker с той же конфигурацией и разрешённым fixture. Runtime health и прямой CLI тест не заменяют эту цепочку. Переход TaskQ не выполнялся; fresh worker chain 0.1.14 не квалифицирована.
